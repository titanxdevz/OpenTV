## Code of conduct

Be respectful and constructive. Assume good faith, and keep discussion focused
on the technical problem. Harassment or personal attacks will not be tolerated.

---

## Before you start

OpenTV is deliberately minimal — one screen, no ads, no feeds, no telemetry.
A change is likely to be accepted if it makes the launcher **faster, cleaner,
or more useful on a low-end TV**. Changes that introduce background services,
network calls, or a heavier dependency footprint will be declined.

For anything substantial, open an issue first so the design can be discussed
before you write code.

## Development setup

### Prerequisites

| Tool | Version |
|---|---|
| JDK | 17 |
| Android SDK platform | 34 |
| Android SDK build-tools | 34.0.0 |

### Setup

```bash
git clone https://github.com/titanxdevz/OpenTV.git
cd OpenTV
```

Create `local.properties` in the project root (it is git-ignored):

```properties
sdk.dir=/path/to/Android/sdk
```

Build and install on a connected device:

```bash
./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

### Target device

Development happens on a **Realme AI Point** — Android 11, 1280×720, 1 GB RAM.
That is the constraint that drives most of the engineering decisions in this
codebase: artwork is decoded as `RGB_565`, downscaled, and disk-cached, and
blurs are generated by upscale rather than by a real convolution.

## Making a change

1. **Branch from `main`.** Use a descriptive name:
   `feature/app-actions`, `fix/focus-restore`, `docs/readme`.

   ```bash
   git checkout -b feature/my-change
   ```

2. **Keep the change focused.** Unrelated refactors belong in their own pull
   request. A reviewer should be able to understand the whole diff in one
   pass.

3. **Match the surrounding style.** The codebase uses 4-space indentation,
   `m`-prefixed fields, and short Javadoc comments on classes and non-obvious
   methods.

4. **Write comments that explain *why*.** The code already says what it does.
   Comments are for the reasoning that is not visible in the code — the
   constraint, the bug being avoided, the device quirk.

5. **Never commit secrets.** No API keys, tokens, passwords, `.jks` files or
   signing material. The `.gitignore` already covers these, but check
   `git diff --cached` before committing.

6. **Update the README** if you changed behaviour, setup steps, or added a
   feature.

## Commit conventions

Commits follow the [Conventional Commits](https://www.conventionalcommits.org/)
specification:

```
<type>(<scope>): <subject>

[optional body]

[optional footer]
```

**Types**

| Type | Use for |
|---|---|
| `feat` | A new user-facing feature |
| `fix` | A bug fix |
| `perf` | A performance improvement |
| `refactor` | Code change with no behaviour change |
| `docs` | Documentation only |
| `test` | Adding or updating tests |
| `build` | Gradle, dependencies, build configuration |
| `ci` | Workflow and CI configuration |
| `chore` | Housekeeping |

**Scopes**

`home`, `row`, `focus`, `settings`, `inputs`, `wifi`, `animation`, `theme`,
`build`, `ci`, `docs`

**Examples**

```
feat(home): add long-press app actions overlay
fix(focus): restore focus position after returning from an app
perf(row): decode banners as RGB_565 to halve bitmap memory
build(deps): bump glide to 4.16.0
ci: add OWASP dependency-check workflow
docs(readme): document the ADB-over-network setup
```

Keep the subject line in the imperative mood, under 72 characters, with no
trailing period.

## Pull request checklist

Fill in the [pull request template](.github/pull_request_template.md) in full —
it is the same checklist a reviewer will use.

Before requesting review:

```bash
./gradlew :app:lintDebug :app:assembleDebug
```

Confirm:

- [ ] The change compiles and the app runs on the target device.
- [ ] D-pad navigation works in all four directions.
- [ ] Focus is restored correctly after returning from an app or the settings
      screen.
- [ ] The layout renders correctly at 1280×720.
- [ ] No new memory pressure — no long-lived `Context` or `Bitmap` references.
- [ ] Any new dependency is pinned to an exact version and permissively
      licensed.
- [ ] `README.md` is updated where behaviour changed.
- [ ] A `CHANGELOG.md` entry is added under *Unreleased*.

## Continuous integration

Every push and pull request triggers the checks below. All of them must be
green before a pull request can be merged.

| Check | What it catches |
|---|---|
| Build, Test, Lint | Compilation errors, failing unit tests, Android Lint issues |
| CodeQL | Java static analysis, taint-tracking vulnerabilities |
| Gitleaks | Committed credentials and API keys |
| OWASP Dependency-Check | Known CVEs in the dependency tree |
| Trivy | Filesystem misconfigurations and leaked secrets |
| Dependency Review | Licence violations and new CVEs introduced by a diff |
| Manifest Policy | New permissions, cleartext traffic, `debuggable` flags |
| License Check | Dependency licence inventory |

### Local pre-flight

Run the same checks the CI runs, before pushing:

```bash
./gradlew :app:lintDebug :app:assembleRelease
```

## Security

**Do not open a public issue for a security vulnerability.**

Report it privately through
[GitHub Security Advisories](https://github.com/titanxdevz/OpenTV/security/advisories/new),
or email <inkmcontop@gmail.com>. See
[SECURITY.md](.github/SECURITY.md) for the full process and timelines.

---

## Reporting bugs

Open an issue using the [bug report template](.github/ISSUE_TEMPLATE/bug_report.yml).
Please include:

- Device model and Android version
- Screen resolution
- OpenTV version
- Exact steps to reproduce
- Relevant `adb logcat -d -s CleanLauncher` output, with any SSID or IP
  address removed
